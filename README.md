# 灯光市人民政府 · v51

Minecraft 像素城市官网。保留原米黄色、绿色、粗边框和硬阴影风格；仅提供浅色界面。

## 结构

- `index.html`、`hotel.html`、`profile.html`、`dm.html`、`notifications.html`、`leaderboard.html`、`admin-v37.html`：七个页面入口。
- `js/app/`：统一页面外壳、请求、弹窗、表单及业务模块；`js/date.js` 处理 D1 UTC 与 ISO 时间。
- `css/style.css`：统一响应式样式；`style.min.css` 保留兼容 URL，不再用破坏 URL/calc 的正则压缩。
- `functions/_core/`：请求验证、权限、资源管理、账号、原子业务提交、数据库迁移。
- `functions/api/`：Cloudflare Pages Functions API，保留原路径；`_middleware.js` 统一错误和写入来源检查。
- `functions/_shared/`：密码散列、WebAuthn 字节/签名校验及 AI 适配器等安全底层。
- `tests/`：Node 测试和真正执行 SQL 的 Python SQLite 适配器。

## 功能

公告、图库、留言和评论、注册审核、登录/退出、每日签到、酒店预订、卡丁车/国际试车、驾照报名、模拟考试、成绩审核、玩家资料和身份卡、密码/通行密钥、私信与通知订阅。

后台包含工单、玩家、报名、赛道、酒店、房型、考试要求、模拟题库、公告、图集、管理员、私信监管和账号安全。图片可填 URL 或选择最大 20 MB 的 PNG/JPEG/WebP/GIF。

管理资源删除会保护历史引用。已有房型/预订/成绩关联的酒店、房型、赛道应停用；业务记录通过审核或关闭归档，避免丢失历史。

## 本地验证

使用 Node 20.19+ 和 Python 3（标准库即可），不需要安装测试依赖。

```sh
npm test
npm run build
npm run dev:local
```

本地测试服务会打印 `http://127.0.0.1:8874`。它在系统临时目录创建隔离 SQLite，使用明确测试账号，不读取 `.dev.vars`，不连接生产 D1。测试账号定义在 `tests/dev-server.mjs`，不能在生产环境运行该脚本。

当前 macOS 的可用 Node：`$HOME/.local/node-v20.19.0-darwin-arm64/bin/node`。若 PATH 中的 Node 无法启动，可直接用此二进制运行 package.json 中的命令。

## 部署和数据

继续使用原 Cloudflare Pages 项目与 `wrangler.toml` 中的 D1 绑定，保持原目录部署方式。`npm run build` 校验模块和静态引用，不更改部署目录。

API 首次启动执行可重入的增量迁移，补齐 v51 所需列与索引；不插入默认赛道、不清空业务表、不重新创建账号。版本记录存于 `lc_schema_versions`。迁移错误会明确返回服务错误，失败后允许重试。

`bookings`、`kart_signups`、`circuit_signups`、`license_signups` 与工单使用 D1 `batch` 同步写入；试车扣费和签到奖励也在原子批次中执行。普通管理员不能重置其他管理员密码，通行密钥必须属于当前账号，跨站写入会被拒绝。

保留原密码散列和 WebAuthn 协议。硬件通行密钥的 Touch ID/Face ID 仍需要在实际设备与正式域名验收。

AI 密钥只使用部署环境变量。默认 OpenAI 服务地址为 `https://api.openai.com/v1`，模型可用 `OPENAI_MODEL` 配置；其他兼容服务必须显式配置 `OPENAI_BASE_URL`。未配置或服务失败时使用明确的自动客服兜底文案。

## 缓存

HTML、脚本和私有接口不从 Service Worker 缓存读取。SW 只缓存公共素材，激活新版时只清理本应用的 `lc-` 缓存。浏览器持久化只保存语言偏好；不保存密码、登录令牌或业务记录。

## 分组导航与工单附件（v52）

工单中心为第一个一级入口，派单为第二个。其他功能合并为市民与账号、酒店业务、赛车业务、驾照与考试、内容管理、私信监管；旧子页 hash 仍可打开对应分组。

工单列表直接显示派单按钮、承办人和附件数。派单页默认显示待处理且未派单的工单，可切换“派给我”。旧留言工单也支持持久化派单。

首页的 Bug 反馈/举报入口和个人工单支持附件。图片最多 20 MiB、视频最多 100 MiB，每单最多 5 个、合计最多 200 MiB。支持分块重试、进度、拖放/粘贴、提交前移除和提交后补充材料。图库、酒店等图片上传共用大图上传功能。

附件复用当前 D1，按 256 KiB 分块保存，避免单行/单请求大小限制。下载按批次拉取分块并流式返回，支持视频 Range 请求；不把完整大文件读入 Worker 内存。图片/视频需要通过 MIME 白名单和文件头检查。未完成上传不能关联工单；关联通过原子事务及唯一约束完成。

举报/Bug 附件只允许所属市民和管理员读取，未提交的草稿仅允许上传者读取；站点图片在管理员保存内容后才公开。未关联且未公开的过期上传在后续上传开始时清理。所有文件上传测试在临时 SQLite 中进行，不在生产创建测试工单或文件。

大量视频会占用 D1 存储容量；当前实现没有创建新存储服务或更改云账号套餐。


## 统一工单、酒店自助与留痕（v53）

- 导航中的市政后台仅对登录中的、双向绑定管理员账号的玩家显示。服务端仍验证管理员权限；仅知道后台地址不会获得管理权限。
- 首页“留言与工单”统一提交留言、服务、Bug、举报玩家、投诉管理员。公开授权默认关闭；同意后仍需管理员审核公开文字。玩家可随时撤回，附件始终私密。旧公开留言保留原公开状态，历史私密 Bug 工单不会自动公开。
- 玩家目录支持真实 ID 匹配与未注册名字手填；管理员投诉使用管理员编号。投诉管理员仅由超管处理，被投诉/举报人回避；派单候选同时排除提交者本人。
- AI 派单只推荐符合权限和回避条件的候选，人工确认后保存。使用现有 OPENAI_API_KEY、OPENAI_BASE_URL、OPENAI_MODEL；配置缺失、超时、无效候选时明确降级为工作量规则推荐。AI 不接收附件；结构化工单的联系字段被剔除。
- 已派工单首次办结奖励承办管理员绑定玩家 10 绿宝石；唯一账本防止重复发放。未绑定玩家时待发，超管绑定后补发。仅关闭不奖励；预订处理不会绕过已派工单的办结确认。
- 超管在“酒店业务 → 酒店老板”创建经营账户，在酒店资料中分配酒店。老板可通过 /hotel-owner.html 登录，也可从绑定玩家的“我的酒店”进入；只管理所分配的酒店、房型及预订。
- **查看、登录、切换 tab、附件预览不留痕。** 业务提交、修改、回复、审核、派单、上传和导出记录操作者身份/编号/姓名、对象、时间与结果。工单有独立办理时间线；超管在“市民与账号 → 操作留痕”按日期/身份/编号查看并导出全部筛选记录。
- 留痕从本版本上线开始，不伪造历史操作。通用日志不保存密码、会话令牌、附件二进制；工单回复历史保留必要的回复内容。数据库增量版本为 57。

验收：57 项自动化测试、99 个 JS 模块、9 个 HTML 入口构建检查通过。真实浏览器已验证本地统一工单提交、投诉编号选择、酒店编辑与历史、人工派单、办结奖励、超管日志、390px 布局。AI 使用模拟服务验收；浏览器 AI 按钮因自动审批拦截未执行，生产 AI 配置和真实模型输出尚未验证。本地 QA 不访问生产数据库。


## 自动派单与历史经验（v54）

新工单、旧兼容留言入口，以及酒店/赛车/驾照业务创建工单后自动执行派单，无须人工确认。已派单和人工取消派单的记录不会被自动覆盖；历史未派单可在派单列表点击“自动补派”。读取页面、登录或查看派单设置不会触发自动处理，也不记录浏览日志。

默认开启：紧急优先 wzc，复杂优先漫画家，既紧急又复杂时紧急优先。默认按管理员名或双向绑定玩家名唯一匹配 `wzc`、`漫画家` / `SIM_漫画家`（大小写归一）；匹配缺失或歧义会在 UI 明示，超管可指定准确管理员编号。被投诉/举报人、提交者本人回避；管理员投诉只派给无需回避的超管。候选每人默认最多 12 个在办工单，可由超管调整。

其余分配参考近 180 天同类工单：由承办人本人回复办结的数量、平均耗时、重开比例及当前工作量，至少 3 个样本才使用历史分数。每次派单重新统计；这是可追溯的历史经验辅助，不是模型训练，也不证明实际服务质量。AI 配置沿用现有环境变量，只接收脱敏文字、候选职责和聚合统计；超时/错误/无效编号时按分工和历史规则自动派单，记录明确区分 AI 与规则。回避、人数上限和指定分工均由服务器执行，AI 无权修改。

“派单 → 调整分工 / 开关”仅超管可修改。自动派单、暂缓理由和规则调整留痕，时间线显示系统操作者、承办人、依据。工单写入优先，派单失败不会撤销已提交工单。原子条件更新与系统日志防止并发重复派单；人工调整、停用或政策变更优先。自动派单后办结同样适用一次性的 10 绿宝石奖励。

数据库版本 58。专项 13 项与原回归 57 项通过（总 70 项），构建 103 JS 模块与 9 HTML 页。本地浏览器实际验证默认分工、开关页面、提交后自动派给 wzc 及可见理由。模型调用通过模拟服务验证，未以真实工单测试生产 AI 服务。


## 旧玩家表密码登录修复（v55）

旧玩家表可能缺少 `last_login_at` 与 `game_id`，之前只在新表定义中提供、未做增量补列。密码验证成功后写入缺失的 last_login_at 会返回 500，且响应尚未设置 Cookie；游戏 ID 缺失还会导致登录态资料读取失败。数据库版本 59 补齐这两列，登录不再写入非必要的 last_login_at，不改变任何原密码/散列/余额/绑定关系。

新增旧结构密码登录、错误密码及版本 58 升级回归测试，验证 Cookie 和后续资料读取；全套 73 项测试通过。API 返回 X-App-Schema-Version 响应头用于识别运行版本，查看和登录仍不产生业务审计日志。线上只验证版本和公开读取，不索取或使用玩家真实密码。
